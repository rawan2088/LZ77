## 🧠 About LZ77

**LZ77** is a lossless data compression algorithm introduced by Abraham Lempel and Jacob Ziv in 1977.

The algorithm compresses data by replacing repeated sequences with references to data that has already appeared. It uses a **sliding window** divided conceptually into:

- **Search Buffer** — contains previously processed characters that can be referenced.
- **Look-Ahead Buffer** — contains the characters currently being examined.

A typical LZ77 token is represented as:

```text
(offset, length, next_character)
```

Where:

- **Offset** — how far backwards the matching sequence starts.
- **Length** — number of characters in the matching sequence.
- **Next Character** — the character immediately following the matched sequence.

For example:

```text
(5, 3, A)
```

means:

> Go 5 characters backwards, copy 3 characters, then append `A`.

## 🔄 Compression Process

The compressor scans the input from left to right.

For each position, it searches the previous portion of the input for the **longest matching sequence** within the search window.

The match is represented using an LZ77 token:

```text
(offset, length, next_character)
```

If no useful match exists, the compressor can represent the current character using a token with zero offset and zero length.

### Example

Given a repeated sequence such as:

```text
ABABABABA
```

the compressor can reference previously encoded characters rather than storing every character independently.

The implementation also handles **overlapping matches**, allowing a match to continue using characters that are being generated by the same match.

This is particularly important for highly repetitive input such as:

```text
ABABABABABABABAB
```

## Decompression

The decompressor reconstructs the original text from the generated LZ77 tokens.

For every token:

1. Move backwards by the specified offset.
2. Copy the specified number of characters.
3. Append the next character, if one exists.

The copying process works directly on the output buffer, which allows overlapping references to be reconstructed correctly.

The goal is:

```text
Original Text
     ↓
  Compress
     ↓
LZ77 Tokens
     ↓
 Decompress
     ↓
Original Text
```

```bash
python main.py
```

Choose:

```text
1
```

Then provide:

Choose:


Then provide:

```text
Compressed file path
Output file path
```

The decompressor reconstructs the original text.

## 📊 Compression Size

The project also calculates the estimated number of bits required to represent the original and compressed data.

The original text is calculated using:

```text
Original Size = Number of Characters × 8
```

For each LZ77 token, the implementation uses:

```text
Token Size =
    Offset Bits
    + Length Bits
    + Next Character Bits
```

The total compressed size is then:

```text
Compressed Size =
    Number of Tokens × Token Size
```

This allows the compression performance to be compared against the original representation.

## Correctness

Since LZ77 is a **lossless compression algorithm**, decompressing the generated tokens should reproduce the original input exactly.

For an input:

```text
Original
```

the expected result is:

```text
decompress(compress(Original)) == Original
```

This property is an important correctness criterion for the implementation.
